# 필기

## 운영체제 제어 프로그램: 시스템의 전체 작동을 감시하고 자원을 제어·관리
    - 감시 프로그램
    - 작업 관리 프로그램
    - 데이터 관리 프로그램

## 럼바우 분석기법 (Rumbaugh / OMT): 그래픽 표기법으로 모델링하는 객체지향 분석 기법

| 구분 | 내용 |
|---|---|
| 분석 절차 | **객 → 동 → 기** |
| 객체 모델링 | 객체 다이어그램 |
| 동적 모델링 | 상태 다이어그램 |
| 기능 모델링 | 자료 흐름도

## 미들웨어: 운영체제와 응용 프로그램 또는 클라이언트와 서버 사이에서 **중개·조정** (통신 및 추가 서비스)

## 객체지향 분석 방법론

| 방법 | 핵심 특징 |
| --- | --- |
| **Coad & Yourdon** | E-R 다이어그램을 사용하여 객체의 행위를 모델링 |
| **Booch** | 미시적(Micro)·거시적(Macro) 개발 프로세스 사용 | 
| **Jacobson** | 유스케이스 중심으로 분석 |

## 교착상태 (Deadlock) 4가지 조건

| 조건 | 영문 | 설명 |
| --- | --- | --- |
| **상호 배제** | Mutual Exclusion | 한 번에 한 프로세스만 공유 자원을 사용할 수 있음 |
| **점유와 대기** | Hold and Wait | 자원을 하나 이상 보유한 상태에서 다른 자원을 얻기 위해 대기 |
| **비선점** | No Preemption | 다른 프로세스가 사용 중인 자원을 강제로 빼앗을 수 없음 |
| **환형 대기** | Circular Wait | 대기 중인 프로세스들이 원형으로 서로의 자원을 요구하며 대기 |

## 분산 데이터베이스 투명성

| 투명성 | 의미 |
| --- | --- |
| **위치 투명성 (Location Transparency)** | 데이터베이스의 실제 물리적 위치를 알 필요 없이 논리적 이름으로 접근 |
| **중복 투명성 (Replication Transparency)** | 데이터가 여러 노드에 중복 저장되어도 하나의 데이터처럼 처리하고 일관성 유지 |
| **병행 투명성 (Concurrency Transparency)** | 여러 사용자가 동시에 트랜잭션을 수행해도 데이터 일관성을 유지하고 각 트랜잭션이 독립적으로 실행되는 것처럼 보장 |
| **장애 투명성 (Failure Transparency)** | 특정 노드나 네트워크 장애가 발생해도 트랜잭션을 정상 처리하거나 복구하여 데이터 무결성 유지 |

## 반정규화: 데이터베이스의 조회 성능 향상 등을 위해 의도적으로 중복을 허용하거나 테이블 구조를 단순화하는 기법이다.

| 구분 | 핵심 목적 | 주요 활용 사례 |
| --- | --- | --- |
| **집계 테이블** | 실시간 연산(SUM, COUNT 등) 부하 감소 | 일별·월별 매출 통계, 부서별 인원수 요약 |
| **진행 테이블** | 복잡한 데이터 처리 단계 및 조인 단순화 | 정산 배치 중간 결과물, 다단계 데이터 이관·가공 |
| **특정 부분 포함 테이블** | 방대한 테이블에서 핵심 데이터만 빠르게 조회 | 전체 회원 테이블 중 활성 회원 또는 핵심 프로필 별도 구성 |


## 개발자 관점의 소프트웨어 품질 특성

| 품질 특성 | 의미 / 핵심 |
| --- | --- |
| **정확성 (Correctness)** | 요구사항에 맞게 정확하게 동작하는 정도 |
| **신뢰성 (Reliability)** | 주어진 조건에서 오류 없이 안정적으로 동작하는 정도 |
| **효율성 (Efficiency)** | 시간·메모리 등 자원을 효율적으로 사용하는 정도 |
| **무결성 (Integrity)** | 데이터 및 시스템을 허가되지 않은 접근·변경으로부터 보호하는 정도 |
| **유연성 (Flexibility)** | 요구사항 변경이나 환경 변화에 쉽게 대응하는 정도 |
| **이식성 (Portability)** | 다른 환경이나 플랫폼으로 쉽게 이전할 수 있는 정도 |
| **사용성 (Usability)** | 사용자가 쉽게 이해하고 사용할 수 있는 정도 |
| **상호운영성 (Interoperability)** | 다른 시스템과 상호 작용하고 연동할 수 있는 정도 |


## 알파 테스트 vs 베타 테스트

| 구분 | 알파 테스트 (Alpha) | 베타 테스트 (Beta) |
| --- | --- | --- |
| **테스트 참여자** | 내부 개발자 및 QA 팀 | 외부 일반 사용자 및 테스터 |
| **테스트 장소** | 회사 내부의 통제된 환경 | 실제 사용자의 환경 |
| **주요 초점** | 기능 검증 및 치명적 버그 수정 | 사용자 경험(UX), 속도 및 피드백 수집 |
| **순서** | 먼저 진행 (1단계) | 알파 이후 진행 (2단계) |

## RIP vs OSPF

| 구분 | RIP | OSPF |
| --- | --- | --- |
| **방식** | 거리 벡터 (Distance Vector) | 링크 상태 (Link State) |
| **최적 경로 기준** | **홉 수** | **링크 비용(Cost)** |
| **알고리즘** | 벨만-포드 (Bellman-Ford) | 다익스트라 (Dijkstra) |
| **최대 홉 제한** | **15홉** (16홉은 도달 불가) | 제한 없음 |
| **갱신 방식** | 주기적 갱신 | 변경 발생 시 갱신 |
| **수렴 속도** | 상대적으로 느림 | 빠름 |
| **적합 규모** | 소규모 네트워크 | 중·대규모 네트워크 |


## 결합도 (Coupling)

| 순위 | 결합도 | 영문명 | 핵심 특징 | 품질 |
| --- | --- | --- | --- | --- |
| **1** | **자료 결합도** | Data Coupling | 필요한 값만 매개변수로 전달 | 가장 좋음 / 가장 약함 |
| **2** | **스탬프 결합도** | Stamp Coupling | 배열·구조체·객체 등 자료구조 전체 전달 | 좋음 |
| **3** | **제어 결합도** | Control Coupling | 다른 모듈의 내부 흐름을 제어하는 요소(Flag 등) 전달 | 보통 |
| **4** | **외부 결합도** | External Coupling | 외부 선언 데이터, 통신 프로토콜, 포맷 등을 참조 | 나쁨 |
| **5** | **공통 결합도** | Common Coupling | 여러 모듈이 공통 데이터 영역(전역 변수)을 공유 | 매우 나쁨 |
| **6** | **내용 결합도** | Content Coupling | 한 모듈이 다른 모듈의 내부 기능이나 자료를 직접 참조·수정 | 가장 강함 / 가장 나쁨 |


## 소프트웨어 프로세스 성숙도 5단계

| 단계 | 영문 | 핵심 내용 | 핵심 키워드 |
| --- | --- | --- | --- |
| **1단계** | Initial (초기) | 명확한 관리 체계나 프로세스가 없음. 개발자의 개인 역량에 의존 | **주먹구구식** |
| **2단계** | Repeatable (반복) | 기본적인 프로젝트 관리 프로세스 수립 | **비용·일정·기능 추적** |
| **3단계** | Defined (정의) | 조직 차원의 표준화된 소프트웨어 프로세스를 문서화하여 관리 | **표준화·문서화·테일러링** |
| **4단계** | Managed (관리) | 소프트웨어 프로세스와 제품 품질을 정량적으로 측정·통제 | **정량적 관리** |
| **5단계** | Optimizing (최적화) | 정량적 피드백과 신기술 도입을 통해 프로세스를 지속적으로 개선 | **지속적 개선·최적화** |


## 데이터베이스 정규형

| 정규형 | 핵심 조건 / 제거 대상 | 해결하는 문제 |
| --- | --- | --- |
| **제1정규형 (1NF)** | 모든 속성이 **원자값(Atomic Value)**을 가짐 | 한 칸에 여러 값이 들어가는 반복 그룹 제거 |
| **제2정규형 (2NF)** | **부분 함수 종속** 제거 | 기본키의 일부에만 종속되는 속성 분리 |
| **제3정규형 (3NF)** | **이행적 함수 종속** 제거 | 기본키가 아닌 일반 속성 간의 종속 관계 분리 |
| **BCNF** | 모든 결정자가 **후보키**가 되도록 분해 | 후보키가 아닌 속성이 다른 속성을 결정하는 문제 해결 |
| **제4정규형 (4NF)** | **다치 종속** 제거 | 독립적인 다대다 관계가 한 테이블에 섞이는 문제 해결 |
| **제5정규형 (5NF)** | **조인 종속** 제거 | 테이블 분해 후 재조인 시 데이터 손실이나 왜곡 방지 |
