## 교착상태 (Deadlock) 4가지 조건

| 조건 | 영문 | 설명 |
| --- | --- | --- |
| **상호 배제** | Mutual Exclusion | 한 번에 한 프로세스만 공유 자원을 사용할 수 있음 |
| **점유와 대기** | Hold and Wait | 자원을 하나 이상 보유한 상태에서 다른 자원을 얻기 위해 대기 |
| **비선점** | No Preemption | 다른 프로세스가 사용 중인 자원을 강제로 빼앗을 수 없음 |
| **환형 대기** | Circular Wait | 대기 중인 프로세스들이 원형으로 서로의 자원을 요구하며 대기 |

## 분산 데이터베이스 투명성

| 투명성 | 의미 |
| --- | --- |
| **위치 투명성 (Location Transparency)** | 데이터베이스의 실제 물리적 위치를 알 필요 없이 논리적 이름으로 접근 |
| **중복 투명성 (Replication Transparency)** | 데이터가 여러 노드에 중복 저장되어도 하나의 데이터처럼 처리하고 일관성 유지 |
| **병행 투명성 (Concurrency Transparency)** | 여러 사용자가 동시에 트랜잭션을 수행해도 데이터 일관성을 유지하고 각 트랜잭션이 독립적으로 실행되는 것처럼 보장 |
| **장애 투명성 (Failure Transparency)** | 특정 노드나 네트워크 장애가 발생해도 트랜잭션을 정상 처리하거나 복구하여 데이터 무결성 유지 |

## 반정규화: 데이터베이스의 조회 성능 향상 등을 위해 의도적으로 중복을 허용하거나 테이블 구조를 단순화하는 기법이다.

| 구분 | 핵심 목적 | 주요 활용 사례 |
| --- | --- | --- |
| **집계 테이블** | 실시간 연산(SUM, COUNT 등) 부하 감소 | 일별·월별 매출 통계, 부서별 인원수 요약 |
| **진행 테이블** | 복잡한 데이터 처리 단계 및 조인 단순화 | 정산 배치 중간 결과물, 다단계 데이터 이관·가공 |
| **특정 부분 포함 테이블** | 방대한 테이블에서 핵심 데이터만 빠르게 조회 | 전체 회원 테이블 중 활성 회원 또는 핵심 프로필 별도 구성 |


## 개발자 관점의 소프트웨어 품질 특성

| 품질 특성 | 의미 / 핵심 |
| --- | --- |
| **정확성 (Correctness)** | 요구사항에 맞게 정확하게 동작하는 정도 |
| **신뢰성 (Reliability)** | 주어진 조건에서 오류 없이 안정적으로 동작하는 정도 |
| **효율성 (Efficiency)** | 시간·메모리 등 자원을 효율적으로 사용하는 정도 |
| **무결성 (Integrity)** | 데이터 및 시스템을 허가되지 않은 접근·변경으로부터 보호하는 정도 |
| **유연성 (Flexibility)** | 요구사항 변경이나 환경 변화에 쉽게 대응하는 정도 |
| **이식성 (Portability)** | 다른 환경이나 플랫폼으로 쉽게 이전할 수 있는 정도 |
| **사용성 (Usability)** | 사용자가 쉽게 이해하고 사용할 수 있는 정도 |
| **상호운영성 (Interoperability)** | 다른 시스템과 상호 작용하고 연동할 수 있는 정도 |


## 알파 테스트 vs 베타 테스트

| 구분 | 알파 테스트 (Alpha) | 베타 테스트 (Beta) |
| --- | --- | --- |
| **테스트 참여자** | 내부 개발자 및 QA 팀 | 외부 일반 사용자 및 테스터 |
| **테스트 장소** | 회사 내부의 통제된 환경 | 실제 사용자의 환경 |
| **주요 초점** | 기능 검증 및 치명적 버그 수정 | 사용자 경험(UX), 속도 및 피드백 수집 |
| **순서** | 먼저 진행 (1단계) | 알파 이후 진행 (2단계) |

## RIP vs OSPF

| 구분 | RIP | OSPF |
| --- | --- | --- |
| **방식** | 거리 벡터 (Distance Vector) | 링크 상태 (Link State) |
| **최적 경로 기준** | **홉 수** | **링크 비용(Cost)** |
| **알고리즘** | 벨만-포드 (Bellman-Ford) | 다익스트라 (Dijkstra) |
| **최대 홉 제한** | **15홉** (16홉은 도달 불가) | 제한 없음 |
| **갱신 방식** | 주기적 갱신 | 변경 발생 시 갱신 |
| **수렴 속도** | 상대적으로 느림 | 빠름 |
| **적합 규모** | 소규모 네트워크 | 중·대규모 네트워크 |


## 결합도 (Coupling)

| 순위 | 결합도 | 영문명 | 핵심 특징 | 품질 |
| --- | --- | --- | --- | --- |
| **1** | **자료 결합도** | Data Coupling | 필요한 값만 매개변수로 전달 | 가장 좋음 / 가장 약함 |
| **2** | **스탬프 결합도** | Stamp Coupling | 배열·구조체·객체 등 자료구조 전체 전달 | 좋음 |
| **3** | **제어 결합도** | Control Coupling | 다른 모듈의 내부 흐름을 제어하는 요소(Flag 등) 전달 | 보통 |
| **4** | **외부 결합도** | External Coupling | 외부 선언 데이터, 통신 프로토콜, 포맷 등을 참조 | 나쁨 |
| **5** | **공통 결합도** | Common Coupling | 여러 모듈이 공통 데이터 영역(전역 변수)을 공유 | 매우 나쁨 |
| **6** | **내용 결합도** | Content Coupling | 한 모듈이 다른 모듈의 내부 기능이나 자료를 직접 참조·수정 | 가장 강함 / 가장 나쁨 |


## 소프트웨어 프로세스 성숙도 5단계

| 단계 | 영문 | 핵심 내용 | 핵심 키워드 |
| --- | --- | --- | --- |
| **1단계** | Initial (초기) | 명확한 관리 체계나 프로세스가 없음. 개발자의 개인 역량에 의존 | **주먹구구식** |
| **2단계** | Repeatable (반복) | 기본적인 프로젝트 관리 프로세스 수립 | **비용·일정·기능 추적** |
| **3단계** | Defined (정의) | 조직 차원의 표준화된 소프트웨어 프로세스를 문서화하여 관리 | **표준화·문서화·테일러링** |
| **4단계** | Managed (관리) | 소프트웨어 프로세스와 제품 품질을 정량적으로 측정·통제 | **정량적 관리** |
| **5단계** | Optimizing (최적화) | 정량적 피드백과 신기술 도입을 통해 프로세스를 지속적으로 개선 | **지속적 개선·최적화** |


## 데이터베이스 정규형

| 정규형 | 핵심 조건 / 제거 대상 | 해결하는 문제 |
| --- | --- | --- |
| **제1정규형 (1NF)** | 모든 속성이 **원자값(Atomic Value)**을 가짐 | 한 칸에 여러 값이 들어가는 반복 그룹 제거 |
| **제2정규형 (2NF)** | **부분 함수 종속** 제거 | 기본키의 일부에만 종속되는 속성 분리 |
| **제3정규형 (3NF)** | **이행적 함수 종속** 제거 | 기본키가 아닌 일반 속성 간의 종속 관계 분리 |
| **BCNF** | 모든 결정자가 **후보키**가 되도록 분해 | 후보키가 아닌 속성이 다른 속성을 결정하는 문제 해결 |
| **제4정규형 (4NF)** | **다치 종속** 제거 | 독립적인 다대다 관계가 한 테이블에 섞이는 문제 해결 |
| **제5정규형 (5NF)** | **조인 종속** 제거 | 테이블 분해 후 재조인 시 데이터 손실이나 왜곡 방지 |

## McCabe Cyclomatic Complexity 

| 항목 | 내용 |
|---|---|
| 의미| 제어 흐름 그래프(Control-flow graph)의 복잡도|
| 공식 | \(M = E - N + 2P\) |
| \(E\) | 간선(Edge)의 수 |
| \(N\) | 노드(Node)의 수 |
| \(P\) | 연결된 컴포넌트(Component)의 수 |

## 해싱 함수

| 해싱 방법 | 설명 |
|---|---|
| 제산법 | 레코드 키를 **해시표 크기보다 큰 수 중 가장 작은 소수**로 나눈 나머지를 주소로 사용 |
| 제곱법 | 레코드 키를 제곱한 뒤 **중간 부분의 비트**를 추출하여 주소로 사용 |
| 폴딩법 | 레코드 키를 여러 부분으로 나눈 뒤 **더하기 또는 XOR 연산**을 수행하여 주소로 사용 |
| 기수 변환법 | 레코드 키를 **다른 진법 체계로 변환**하여 주소로 사용 |
| 무작위법 | 난수(Random)를 이용하여 해시 주소를 결정 |
| 숫자분석법 | 키를 구성하는 숫자의 분포를 분석하여 해시 주소로 사용 |

### 해시 충돌 방지법

| 방법 | 세부 방법 | 설명 |
|---|---|---|
| 체인법 | - | 충돌한 레코드들을 연결 리스트 등의 자료구조로 연결하여 저장 |
| 개방주소법 | 선형조사 | 충돌이 발생하면 일정한 간격으로 다음 주소를 순차적으로 조사 |
| 개방주소법 | 이차조사 | 충돌이 발생하면 조사 간격을 제곱 형태로 증가시키며 빈 주소를 탐색 |

## 순차 파일(Sequential File)

| 항목 | 내용 |
|---|---|
| 정의 | 레코드를 논리적 순서에 따라 보조기억장치의 **연속된 물리적 공간**에 차례대로 저장하는 파일 편성 |
| 저장 구조 | 논리적 순서와 물리적 저장 순서가 같으며, 중간에 빈 공간이 없어 **기억 공간 효율(기록 밀도)이 높음** |
| 접근 방식 | 처음부터 차례대로 읽는 **순차 접근**만 가능 |
| 특정 레코드 접근 | 특정 레코드를 바로 찾을 수 없으며 앞선 레코드를 거쳐야 함 |
| 활용 용도 | 대화식 처리보다 전체 데이터를 한 번에 처리하는 **일괄 처리(Batch Processing)** |
| 장점 | 구조가 단순하여 구현하기 쉽고, 연속적인 읽기에서 처리 속도와 저장 공간 효율이 높음 |
| 단점 | 중간에 레코드를 삽입하거나 삭제할 경우 뒤따르는 데이터의 이동 부담이 발생 |

## 네트워크 계층별 장비

### L1 — 물리 계층

| 장비 | 설명 | 주요 특징 |
|---|---|---|
| NIC (Network Interface Card, 랜카드) | 컴퓨터와 네트워크를 연결하여 신호를 주고받는 장치 | 고유한 **MAC 주소** 보유 |
| 리피터 (Repeater) | 전송 과정에서 약해진 신호를 재생·증폭하여 먼 거리까지 전달 | 신호 재생·증폭 |
| 허브 (Hub) | 여러 대의 기기를 연결하는 장치 | 연결된 여러 기기로 신호 전달 |

### L2 — 데이터 링크 계층

| 장비 | 설명 | 주요 특징 |
|---|---|---|
| 브리지 (Bridge) | 두 개의 LAN을 연결하여 더 큰 LAN을 구성 | **MAC 주소**를 기반으로 프레임 필터링 |
| 스위치 (Switch, L2 스위치) | 브리지와 유사하지만 하드웨어 기반으로 동작하여 처리 속도가 빠름 | MAC 주소를 학습하고 목적지 포트로만 프레임 전달 |

### L3 — 네트워크 계층

| 장비 | 설명 | 주요 특징 |
|---|---|---|
| 라우터 (Router) | 서로 다른 네트워크를 연결하고 최적의 경로를 찾아 패킷 전달 | **IP 주소** 기반, RIP·OSPF·BGP 등의 라우팅 프로토콜 사용 |
| L3 스위치 | 2계층 스위칭 기능과 3계층 라우팅 기능을 결합 | 스위칭 + 라우팅 |

### 상위 계층 / 기타 장비

| 장비 | 계층 | 설명 |
|---|---|---|
| L4 스위치 | 4계층(전송 계층) | TCP/UDP **포트 정보**를 활용하여 트래픽을 분산(로드 밸런싱) |
| 게이트웨이 (Gateway) | 상위 계층 / 프로토콜 변환 | 서로 다른 네트워크 또는 프로토콜을 연결하는 역할 |

## 세션 하이재킹 탐지 방법

| 탐지 방법 | 설명 |
|---|---|
| 비동기화 상태 탐지 | 공격자가 TCP 시퀀스 번호를 조작하거나 예측하여 개입하면 클라이언트와 서버 간 시퀀스 번호가 어긋나 패킷 순서가 맞지 않는 상태가 발생하는 것을 탐지 |
| ACK 스톰 탐지 | 시퀀스 번호 불일치로 양쪽 시스템이 서로 다른 시퀀스 번호를 확인하려 하면서 **ACK 패킷이 과도하게 주고받아지는 현상**을 탐지 |
| 패킷 유실 및 재전송 증가 탐지 | 세션 탈취나 간섭 과정에서 정상 패킷이 손실되거나 시퀀스 번호가 맞지 않아 특정 세션의 **패킷 유실 및 재전송 횟수가 급증**하는 현상을 탐지 |
| 예상치 못한 접속의 RST 탐지 | 공격자가 기존 세션을 끊고 가로채기 위해 **RST 패킷**(reset)을 보내면서 연결이 갑작스럽게 종료되거나 초기화되는 현상을 탐지 |

### 데이터 흐름도(DFD)의 구성요소

| 구성요소 | 표기 |
|---|---|
| 프로세스 (Process) | 원 또는 둥근 사각형 |
| 데이터 흐름 (Data Flow) | 화살표 |
| 데이터 저장소 (Data Store) | 두 평행선 또는 한쪽이 열린 직사각형 |
| 외부 엔티티 (External Entity / 단말) | 사각형 |


### 데이터베이스 회복 기법

| 회복 기법 | 설명 | 핵심 특징 |
|---|---|---|
| 즉시 갱신 (Immediate Update) | 트랜잭션 수행 중 변경 내용을 실제 DB에 즉시 반영하고 변경 전·후 내용을 로그에 기록 | **Redo + Undo** |
| 지연 갱신 (Deferred Update) | 트랜잭션 완료 시까지 DB에 반영하지 않고 로그에 기록한 후 완료 시 DB에 반영 | **Redo만 사용**, Undo 불필요 |
| 체크포인트 (Checkpoint) | 일정 주기마다 검사점을 두고 장애 발생 시 가장 최근 검사점 이후의 트랜잭션을 대상으로 복구 | 로그 스캔 범위 감소 |
| 그림자 페이징 (Shadow Paging) | 현재 페이지 테이블과 별도로 그림자 페이지 테이블을 유지하고 변경 내용을 현재 페이지에 반영 | **로그를 사용하지 않음** |


### 병행제어 기법

| 기법 | 설명 | 핵심 특징 |
|---|---|---|
| 로킹 (Locking) | 데이터 접근 전에 잠금을 설정하여 다른 트랜잭션의 접근을 제한 | 로킹 단위가 작으면 병행성↑·오버헤드↑ |
| 타임스탬프 순서 (Timestamp Ordering) | 트랜잭션에 타임스탬프를 부여하고 정해진 순서대로 실행 | **교착상태(Deadlock) 없음** |
| 최적 병행 수행 (Optimistic Concurrency Control) | 실행 중 검사를 생략하고 커밋 직전에 충돌 여부를 검증 | 충돌이 적은 환경에 적합 |
| 다중 버전 기법 (MVCC) | 데이터 갱신 시 새로운 버전을 생성하여 읽기 작업의 차단을 줄임 | 여러 데이터 버전 유지 |


### 시간 구역성 (Temporal Locality)

| 항목 | 내용 |
|---|---|
| 개념 | 프로세스가 실행되는 동안 한 번 참조한 기억 장소를 가까운 시간 내에 다시 참조할 가능성이 높은 성질 |
| 구역성 분류 | 구역성(Locality, 지역성)의 한 종류 |
| 핵심 | 특정 페이지나 기억 장소를 일정 시간 동안 집중적으로 액세스 |
| 주요 예시 | 반복문(Loop), 스택(Stack), 부프로그램/서브루틴(Subroutine), 카운팅 변수, 집계(Totaling) 변수 |


### 데이터 송수신 보안의 핵심 요소

| 요소 | 설명 |
|---|---|
| 기밀성 (Confidentiality) | 인가된 사용자만 정보에 접근할 수 있도록 보호 |
| 무결성 (Integrity) | 데이터가 허가 없이 변경·훼손되지 않도록 보호 |
| 가용성 (Availability) | 필요한 시점에 인가된 사용자가 데이터와 시스템을 이용할 수 있도록 보장 |
| 인증 (Authentication) | 사용자의 신원을 확인 |
| 부인 방지 (Non-repudiation) | 송수신자가 자신의 행위를 부인하지 못하도록 보장 |


### 강제적 접근통제의 보안 모델

| 보안 모델 | 강조하는 보안 요소 | 핵심 내용 |
|---|---|---|
| 벨-라파듈라 (BLP) | **기밀성** | No Read Up + No Write Down |
| 비바 (Biba) | **무결성** | No Read Down + No Write Up |
| 클락-윌슨 (Clark-Wilson) | **무결성** | 지정된 프로그램/트랜잭션을 통해서만 객체에 접근 |
| 만리장성 (Brewer-Nash / Chinese Wall) | **이해 충돌 방지** | 주체의 과거 접근 이력에 따라 동적으로 접근 통제 |
